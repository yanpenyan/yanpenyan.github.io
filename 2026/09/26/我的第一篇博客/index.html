我的第一篇博客

发表于2026-09-26|更新于2026-09-26|博客
|浏览量:
在听了社长讲话后，我便想拥有一个完全属于自己的博客，不依附第三方平台，可以自由写笔记、整理学习碎片。在社长的推荐下，我选择用 Hexo + GitHub Pages 搭建静态博客，本以为复制几条命令就能搞定，实际过程踩了不少坑，记录一下完整经历。

一、前期准备
搭建博客前需要装好两个基础环境：Node.js 和 Git。
Node.js 不用强制安装在C盘，可以自定义安装到D盘，但是安装结束一定要确认环境变量生效。我最开始安装完，打开CMD输入 node -v 提示命令不存在，折腾很久才明白：安装程序修改环境变量之后，必须关掉旧的终端窗口重新打开，否则系统读不到新配置。
装好环境，全局安装 Hexo，初始化本地博客文件夹。本地执行  hexo s ，浏览器打开  http://localhost:4000 ，看到默认博客页面那一刻，本地博客就跑通了。本地预览一切正常，真正的挑战是部署到 GitHub。

二、部署到 GitHub：踩坑最多的环节
GitHub Pages 的原理，就是把静态网页文件推送到特定名称仓库，GitHub 直接帮我们对外提供网页访问。
我一开始尝试 SSH 方式部署，生成 SSH 密钥，把公钥粘贴到 GitHub 设置里。执行：

bash

ssh -T git@github.com  

直接报错： ssh: connect to host github.com port 22: Connection refused 。

22端口被限制，没招了，便改用443。
配置修改完成，执行

bash

hexo clean
hexo g
hexo d
 
清理缓存、生成静态页面、部署上传。命令执行没有报错，仓库也看到上传的文件，等待一小段时间，终于成功打开我的个人博客地址。

三、搭建之后，我学到什么
整个过程大量时间不是写博客内容，而是解决环境变量、网络连接、部署认证的各种报错。很多教程给出的命令是理想环境下的效果，现实中网络、系统设置都会带来意外问题。
1. 环境安装完，一定要重启终端，不然环境变量不生效；
2. 每次更新博客，固定三步： hexo clean  →  hexo g  →  hexo d ；
3. 部署完成网页没有更新，大概率是浏览器缓存，强制刷新或者清除缓存即可。
博客搭建完成，才是真正的开始。以后高数、线性代数的笔记，编程踩过的坑，日常的思考都可以往这里记录。它不仅仅是一个网页，更是属于自己的线上笔记本。

在此感谢社长的教程以及豆包的辅助
